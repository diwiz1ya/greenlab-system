2) Login and Session Controls

Operator sequence

  1. Enter credentials.
  2. Submit sign in.
  3. Verify station workspace is loaded.
  4. Use Log out before role handover.

Why this step matters

  • Prevents role mixing and wrong station actions.
  • Keeps audit trail tied to actual operator session.
  • Ensures permissions are aligned with current station.

Control dictionary

Control Behavior Reason Validation
Username inputSets operator identityRoutes to permitted station contextUser can submit login form
Password inputAuthenticates sessionBlocks unauthorized accessSession opens without auth error
Sign inSubmits login requestStarts active shift sessionWorkspace and role header visible
Log outCalls logout and resets sessionEnds session before next operator startsReturns to login page

Support endpoint used by logout flow: POST /api/logout

3) Sorting Station and Basket Breakdown Modal

Operator sequence

  1. Open target order from unsorted queue.
  2. Add one or more baskets by scan.
  3. For each basket, set category and counts, attach photos if needed.
  4. Review preview and submit create/update.
  5. Use return-to-sorting only for full rollback of current basket set.

11) Go-live Validation Checklist

Mandatory pre-launch checks

  1. Login works for all roles.
  2. Sorting create/update/rollback and label print work.
  3. Washing and drying complete load plus unload cycle.
  4. QC pass and HOLD actions execute correctly.
  5. Ironing scan transitions basket to pickup.
  6. Pickup assembly, placement, and final issue work end-to-end.
  7. Manager sync, history, reports, and ready-order modals work.

Frequent failure patterns

  • White screen: hard refresh and verify server health endpoint.
  • Disabled button: previous required scan step not completed.
  • Scan error: wrong station context or invalid QR prefix.
  • Placement submit error: invalid BIN or location mapping.
  • Manager action blocked: case is not in expected status gate.
